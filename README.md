# GNOME PR Indicator

Пользовательское расширение для GNOME Shell 46: последние PR одного приватного
репозитория GitHub и состояния их проверок в верхней панели.

Перед первым обновлением укажите свой репозиторий в настройках вместо `owner/repository`.
Начальные значения: 3 последних PR, обновление раз в 60 секунд.
Все перечисленные параметры доступны в окне настроек без редактирования кода.
Работа ChatGPT, Node.js и GitHub CLI для индикатора не требуется.

## Установка

Не используйте sudo. Архив уже содержит скомпилированную схему GSettings.

```bash
gnome-extensions install --force /полный/путь/gnome-pr-indicator@extensions.local.zip
```

Если расширение устанавливается впервые и GNOME его ещё не видит, сохраните работу,
выйдите из сеанса и войдите снова. В Wayland нельзя перезапускать Shell через Alt+F2 r.
Затем:

```bash
gnome-extensions enable gnome-pr-indicator@extensions.local
gnome-extensions prefs gnome-pr-indicator@extensions.local
```

Для повторной установки сделайте копию существующего каталога расширения, прежде
чем использовать --force. Изменённые JS-модули могут потребовать повторного входа.

Зависимости Ubuntu 24.04: gjs, gnome-shell, gir1.2-soup-3.0, gir1.2-secret-1,
gir1.2-adw-1. Они обычно уже установлены. Поддержка других версий Shell не заявлена.

## Авторизация приватного репозитория

Подключение GitHub в ChatGPT не авторизует расширение.
В текущей версии для чтения Checks API приватного репозитория нужен PAT classic.
Ранее предложенный fine-grained PAT для этой функции не подходит: GitHub указывает
Checks API в списке ограничений fine-grained PAT.
Официальная документация: https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference

1. Откройте https://github.com/settings/tokens/new — создание Personal access token (classic).
2. Note: GNOME PR Indicator. Укажите срок действия, например 30 дней.
3. В Select scopes отметьте repo: это требуемый GitHub scope для чтения checks
   приватного репозитория. Дополнительные admin/delete_repo/workflow scopes не нужны.
4. Нажмите Generate token и скопируйте полученный токен.
5. В настройках расширения введите токен в поле «Токен GitHub», нажмите
   «Сохранить», затем «Проверить». Токен не отправляйте в чат.

Важно: classic repo предоставляет широкие права на приватные репозитории аккаунта,
включая запись. Его нельзя ограничить одним репозиторием. Само расширение выполняет только
GET-запросы. Если такие права токена не подходят, не создавайте его: для доступа
только к выбранному репозиторию с правами чтения потребуется отдельная интеграция GitHub App,
которую эта версия пока не настраивает автоматически.

Токен хранится только в GNOME Keyring через libsecret. Разблокируйте системную
связку ключей, если сохранение недоступно. Открытого резервного хранения нет.
Кнопка «Удалить» удаляет сохранённый токен. Сброс параметров токен не удаляет.
При смене репозитория токен должен иметь доступ к новому репозиторию.

В режиме обычного автообновления сохранение/смена токена может вызвать загрузку
данных. В режиме «только вручную» запрос выполняется по «Проверить» или «Обновить».

## После повторного входа в систему

При автоматическом входе без пароля GNOME Keyring может оставаться заблокированным.
Это не удаляет токен. Расширение показывает отдельный статус блокировки и не открывает
диалог пароля во время фонового обновления.

1. Откройте настройки GNOME PR Indicator.
2. В разделе «Подключение» нажмите «Разблокировать».
3. В системном окне GNOME введите пароль связки ключей (он может отличаться от
   текущего пароля пользователя). GitHub-токен заново вводить не нужно.
4. Нажмите «Проверить» или в меню индикатора «Обновить».

Разблокировка действует до завершения сеанса или ручной блокировки связки.
Пустое поле «Токен GitHub» нормально: сохранённый токен туда не подставляется.
Строка «Авторизация» показывает, сохранён и доступен ли токен.
Автоматический вход и пароль связки расширение не меняет.

## Настройки

- Подключение: owner/repository, сохранение/проверка/удаление токена.
- PR: количество 1–10; дата создания/обновления; прямой/обратный порядок;
  фильтры открытых, черновиков, слитых и закрытых без слияния; фильтр автора.
  Фильтры применяются до ограничения количества. При редком фильтре автора
  загрузка может потребовать просмотра многих страниц GitHub API.
- Обновление: периодическое, при включении расширения, при открытии меню;
  интервал — любое целое число от 1 до 2147483647 секунд; «только вручную»
  исключает все автоматические запросы. Ручная кнопка доступна независимо
  от автообновления. Лимит GitHub ограничивает фактическую частоту запросов.
- Панель: слева/по центру/справа; значок, количество PR, номера PR, состояние PR, сводка.
  Для каждого положения — независимые внешние отступы слева и справа (0–500 логических px).
  Они находятся в группах «Отступы: Слева», «Отступы: По центру», «Отступы: Справа».
  Слева индикатор располагается после системных элементов: его отступы не сдвигают
  переключатель рабочих столов.
  Начальное значение 0 сохраняет прежнюю геометрию; отступы применяются сразу.
- Оформление: состояния PR отмечаются цветом в панели и меню: открытый — зелёный,
  черновик — серый, закрытый без слияния — красный, слитый — фиолетовый.
  Цвета отключаются независимо от видимости меток. Они не обозначают состояние CI.
  При выключении всех элементов остаётся минимальная кнопка PR.
- Меню: номер, название, состояние, сводка, отдельные проверки и время
  последнего обновления; ссылки можно отключить.
- Проверки: GitHub Checks и классические commit statuses включаются независимо.
  Отключённые источники не запрашиваются. Фильтр деталей: все, выполняющиеся
  или проблемные. Он не скрывает ошибки в общей сводке.
- Сброс параметров сохраняет токен. Системные уведомления в первой версии отсутствуют.

Интервал и прочие параметры применяются без перезапуска. Частота 1 секунда технически
допустима, но быстро расходует API quota. Для обычной работы начните с 60 секунд.
Постоянных анимаций и отдельного фонового браузерного процесса нет.

## Значения статусов

✓ — успешные проверки; ◷ — выполняются/ожидают; ✕ — ошибка;
⊘ — отменены; ↷ — skipped/neutral; — — проверок нет; ? — данные неполные;
− — мониторинг проверок отключён.

Ошибка остаётся в сводке, даже если другие проверки ещё выполняются.
Отсутствие проверок, отказ доступа и отключённые источники не обозначаются успехом.
Отображаются актуальные результаты check runs и classic statuses для head SHA,
а при наличии — отдельно для тестового merge SHA открытого PR. Метки head/test-merge
помогают различить источник. Результаты не означают, что удовлетворены все правила
защиты ветки или что PR можно сливать. Подробные Actions steps и логи не загружаются.

## Ошибки и ограничения

- Нужна авторизация: сохраните токен или замените истёкший.
- Нет доступа: проверьте имя репозитория, разрешения и одобрение токена.
- Частично недоступные checks: используйте PAT classic с repo; fine-grained PAT не подходит для Checks API.
- Данные устарели: последняя загрузка не удалась либо поменялись фильтры;
  старые данные остаются с явной отметкой. При смене репозитория/токена очищаются.
- Rate limit: дождитесь указанного времени; ручная кнопка не обходит лимит.
- Настройки и ручное обновление остаются доступны при любой ошибке.

Диагностика без вывода токена:

```bash
gnome-extensions info gnome-pr-indicator@extensions.local
journalctl --user -b -o cat | rg -i 'gnome-pr-indicator|JS ERROR'
```

## Отключение, удаление и откат

```bash
gnome-extensions disable gnome-pr-indicator@extensions.local
```

Перед удалением при необходимости удалите токен через настройки. Удаление самого
расширения не гарантирует удаление записи GNOME Keyring:

```bash
gnome-extensions uninstall gnome-pr-indicator@extensions.local
```

Для отката установите сохранённый старый архив/каталог и повторно войдите в сеанс.
Расширение не меняет репозиторий, не сливает PR и не запускает workflow.

## Проверки и сборка из исходников

```bash
for f in tests/*.test.js; do gjs -m "$f" || exit; done
python3 -m unittest discover -s tests -p '*_test.py'
gjs -m tools/check-syntax.js
glib-compile-schemas --strict --dry-run schemas
python3 tools/package.py --output /tmp/gnome-pr-indicator@extensions.local.zip
```

Для разработки схемы генерируются из lib/settings.js: `gjs -m tools/schema.js`.
Offline tests не подтверждают действительность вашего токена и работу интерфейса
в текущем GNOME-сеансе: это проверяется отдельно после установки.

## Профиль: последние открытые PR и черновики

В настройках раздела «PR» включите «Открытые PR» и «Черновики», выключите
«Слитые PR» и «Закрытые без слияния». Выберите количество 3, сортировку по дате
создания и порядок «Сначала новые». Фильтры применяются до выбора последних PR.
Эти параметры сохраняются локально, их можно изменить в любой момент.

## Что хранится в репозитории

Исходный код, тесты и инструкции. GitHub-токен вводится каждым пользователем
локально и хранится в GNOME Keyring. Токены, связки ключей и экспорт настроек
пользователя в репозиторий не включаются.
